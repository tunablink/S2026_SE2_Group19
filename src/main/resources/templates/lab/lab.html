A01: Broken Access Control - Lab Walkthrough

This page explains each step of the lab with visual guidance. Learners can follow the workflow, review screenshots, and understand what should happen before moving to the next step.

Category: Web Security
Estimated Time: 15 min
Format: Guided Practice

01

Open the Lab Interface

Start from the lab dashboard and read the objective.

Starting Point

Begin by opening the selected lab from your simulator page. The learner should first read the objective and understand what type of issue is being demonstrated.

  • Locate the lab title and short description.
  • Review the objective before interacting with the page.
  • Identify which user account is currently active.
Tip: Keep the instructions short and visual. This page is for guiding the learner, not overwhelming them with theory.

Screenshot: Lab overview screen

02

Inspect the Current User Profile

Observe the data shown on screen and the visible request pattern.

Observation

At this step, the learner checks the profile screen inside the practice lab and notices how the application identifies the current user.

  • Look at the profile information being displayed.
  • Pay attention to any ID value shown in the URL or request panel.
  • Compare the displayed data with the active account role.
Warning: Do not clutter this area with too many paragraphs. Use short blocks and screenshots for clarity.

Screenshot: User profile area inside the lab

03

Modify the Request Parameter

Demonstrate the action visually inside the simulator.

Action Step

The learner edits the request value within the lab environment. This step should show exactly where the change happens and what input is being modified.

  • Highlight the editable parameter visually.
  • Use arrows, numbered labels, or cropped screenshots.
  • Explain the action in one or two short sentences.
Best practice: Use one large image rather than several small images if the action needs focus.

Screenshot: Editing the request parameter in the lab

04

Review the Output

Show the result and explain why the behavior is insecure.

Outcome

After the action is performed, the learner sees the new output on the page. This is where you explain what changed and why it matters.

  • Point out the unauthorized information now visible.
  • Describe the security issue in simple language.
  • Keep the explanation short and tied directly to the screenshot.
Expected Result: The learner understands that the application returned data it should not have exposed.

Screenshot: Result after modifying the lab input

05

Enable Defense Mode and Compare

Show how the protected version changes the behavior.

Defense View

The last step helps the learner compare the vulnerable flow with the protected one. This is where your lab becomes more educational and complete.

  • Display the same action in protected mode.
  • Show the blocked response, permission error, or sanitized output.
  • End with a short explanation of the fix.
This section is ideal for a “Before vs After” visual comparison if you want a stronger UX.

What the learner should remember
